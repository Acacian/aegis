# Project Governance

Aegis is maintained by [@Acacian](https://github.com/Acacian).

## Decision Making

- **Minor changes** (docs, typos, small fixes): Merged by maintainer after review.
- **New features / adapters**: Discussed in an issue or Discussion first, then implemented via PR.
- **Architecture changes**: Require an Architecture Decision Record (ADR) captured as a GitHub issue with the `adr` label.
- **Breaking changes**: Must be discussed in a GitHub Discussion and documented in CHANGELOG.md.

## Roles

| Role | Responsibilities |
|------|-----------------|
| **Maintainer** | Merge PRs, release versions, set roadmap |
| **Contributor** | Submit PRs, report bugs, suggest features |
| **Reviewer** | Review PRs, provide feedback (open to anyone) |

## Release Process

1. Features are developed on feature branches
2. PRs target `main` and require CI to pass
3. Releases are tagged (`v0.x.y`) and published to PyPI via GitHub Release
4. Release notes are auto-generated by Release Drafter
